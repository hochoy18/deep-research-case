DEEP RESEARCH · BACKEND

KB 知识库模块 · 功能说明

跨研究循环的长期记忆层 —— 把每次 web 搜索的摘要拆解为可复用的原子事实存入向量库， 下次研究相似主题时先检索已知事实注入提示词，避免重复搜索。

1. 目录结构

src/agent/kb/ ├── __init__.py # 统一出口（FactStore / FactExtractor / 生命周期策略） ├── extractor.py # 写入侧：LLM 从摘要抽取结构化事实 ├── fact_store.py # 存储与检索：Milvus 封装 + embedding + 过滤衰减 └── lifecycle.py # 时效性策略：四种模式的开关与阈值配置
文件行数职责
__init__.py42对外暴露 FactStore、FactExtractor、生命周期常量与判定函数
extractor.py142调用 LLM 将摘要拆成 {fact, source_url, confidence, fact_category} 列表
fact_store.py481Milvus 集合管理、向量检索、过滤衰减、rerank 集成、embedding 重试
lifecycle.py81四种运行模式的枚举、TTL 配置、should_* 行为开关

2. 在 application 中的位置

KB 模块是 Deep Research 系统的长期记忆层。每次新研究会都涉及大量 web 搜索， 若不持久化，同一主题第二次研究仍需从零开始。KB 让系统具备跨会话、跨运行的"已知事实"积累能力。

KB 在主图中的位置 —— ResearchAgent 的两个节点（_generate_queries 与 _web_search） 分别从 KB 读、写。fresh_level 由 MainGraph 的 Plan 节点注入 state。

3. 数据流闭环

写入侧（_web_search 末尾）：摘要 → FactExtractor → URL 还原 → FactStore → Milvus。 读取侧（_generate_queries）：Milvus → FactStore.query → known_facts → 提示词。两者通过 Milvus 形成闭环。

4. 核心组件详解

4.1 FactExtractor（extractor.py）

写入侧入口。输入一段已经 LLM 摘要过的搜索文本，输出结构化事实字典列表。 它不接触 Milvus，只做"文本 → 结构"这一件事。

EXTRACTION_INSTRUCTIONS 提示词设计

提示词的 7 条约束及其工程意图：

#约束意图
1独立可验证的单句陈述，避免复合句复合句无法单独做向量检索，也无法单独判定时效
2标注来源 URL（从摘要的 [来源名](url) 提取）与 web_searcher_instructions 的输出格式形成契约
3confidence 三档打分让后续检索能按证据强度过滤
4fact_category 五类标注决定每条事实的生命周期（TTL）
5不提取泛陈述无信息量的事实会污染检索结果
6每条 ≤ 80 字控制 embedding 的语义聚焦度
7最多 10 条控制单次写入量与 token 成本

confidence 三档标准

区间含义
0.9 – 1.0摘要明确引用具体数据/事件
0.7 – 0.8摘要中有较明确的表述
0.5 – 0.6摘要中隐含但未直接说明
关键区分
confidence 衡量的是摘要文本对这条陈述的支撑程度，而非事实本身的真实性。 这是可靠打分（有明确文本依据），不是幻觉性的主观判断。

extract() 执行流程

extract() 七步流程。任何异常都被吞掉返回空列表——这是 KB 的一贯设计：失败就降级，不影响主流程。

_validate() 五道过滤

过滤规则处理
非 dict 元素跳过
fact 文本为空 / < 10 字跳过
confidence 缺失默认 0.7（"较明确表述"档）
confidence 越界min(1.0, max(0.0, x)) clamp
fact_category 缺失默认 "strategy"（90 天 TTL）
累计满 10 条break 截断

4.2 FactStore（fact_store.py）

Milvus 的封装层，用 PyMilvus 2.5 的 MilvusClient API。

存储结构

字段类型说明
vectorfloat[]embedding 向量（默认 1024 维）
fact_textstring事实陈述
source_urlstring来源（已还原为真实 URL）
research_topicstring触发本次搜索的研究主题
confidencefloat抽取时的原始置信度
fact_categorystring时效性类别
created_atintUnix 时间戳，衰减与过滤的基准

集合配置：COSINE 距离、auto_id、enable_dynamic_field，索引类型 IVF_FLAT（nlist=128）。

query() 四阶段流水线

置信度衰减公式

decay_factor = max(0.3, 1.0 - age_days / (effective_max_age * 2))
confidence   = raw_confidence * decay_factor

下限 0.3 意味着即使事实非常老旧也不会被打到零分。 在 lifecycle 模式下，effective_max_age 使用该类别的 TTL；TTL 为 None 的类别（如 historical）回落到 180 天。

_embed() 重试策略

错误类型状态码 / 现象处理
永久错误401 / 403 / 400立即抛 KBEmbeddingFatalError，不重试
永久错误JSON 解析 / 结构错误立即抛 KBEmbeddingFatalError
429 限流HTTP 429退避重试（3s / 6s），耗尽抛 KBEmbeddingError
服务端错误HTTP 5xx退避重试（2s / 4s），耗尽抛 KBEmbeddingError
网络错误Connection / Timeout退避重试（1.5s / 3s），耗尽抛 KBEmbeddingError
未知异常—保守重试，耗尽抛 KBEmbeddingError

配置 fallback 链：EMBEDDING_BASE_URL → LLM_BASE_URL；EMBEDDING_API_KEY → APP_TOKEN。

同步 / 异步现状
query() 和 add_facts() 仍是同步阻塞调用。当前 research 节点也是同步，所以不构成问题， 但若后续节点异步化，需要用 asyncio.to_thread 包裹（目前只有 _aembed() 做了这层准备）。

4.3 Lifecycle 策略（lifecycle.py）

纯配置 + 判定函数，无状态。由 KB_LIFECYCLE_MODE 环境变量控制，默认 freshness，非法值静默回落。

模式 过滤 衰减 年龄标签 提示词措辞 效果
off✗✗✗硬性禁止重搜KB 退化为纯语义检索
inform✗✗✓鼓励重新验证全部交给 LLM 自行判断
freshness✓✓✓鼓励重新验证按 fresh_level 统一阈值
lifecycle✓✓✓鼓励重新验证按 fact_category 逐条判断

freshness 模式的统一阈值

fresh_level最大年龄适用场景
high7 天市场份额、价格、排名
medium30 天产品、战略、趋势
low180 天技术原理、历史

按类别的 TTL（lifecycle 模式）

fact_categoryTTL覆盖内容
market_data7 天市场份额、价格、排名、增长率、营收数据
product_info30 天产品功能、规格、版本、发布信息
strategy90 天公司战略、投资方向、合作、收购

四个模式形成"信任 KB → 不信任 KB"的连续光谱：off 完全不干预，lifecycle 精细到按事实本身的 category 控制生命周期。

6. 单例与降级机制

在 research_agent.py 中，KB 通过模块级单例延迟初始化：

_kb_store: FactStore | None = None
_kb_extractor: FactExtractor | None = None

def _get_kb_store() -> FactStore | None:
    global _kb_store
    if _kb_store is None:
        try:
            _kb_store = FactStore()
        except (KBConnectionError, KBConfigError) as exc:
            logger.warning(...)
            _kb_store = False  # 哨兵
    return _kb_store if _kb_store is not False else None
优雅降级
初始化失败时把 _kb_store 设为 False 作哨兵，后续调用直接返回 None。 Milvus 起不来整个系统照常运行，只是失去长期记忆。

异常处理：读写对称的三段式

异常类型语义日志级别
KBConnectionError / KBEmbeddingError瞬时错误，下次可能恢复warning
KBConfigError / KBEmbeddingFatalError永久错误，需人工修复error
Exception未知兜底warning

8. 已知问题与改进点

1. JSON 数组回落路径缺失
Post._extract_json() 只按 {...} 匹配对象，不处理 [...] 数组。 LLM 漏掉围栏时静默丢弃整批事实。需要增加方括号配对扫描。
2. relevance 回落边界问题
rerank_scores.get(orig_idx) or cand["distance_score"]， 若 rerank 分数恰为 0.0 会被 or 误判 falsy 而错误回落到距离分数。严格说应改为 is not None。
3. float() 失败会连坐整批
单条 confidence 为非数值字符串时，异常在 _validate 内抛出，导致整批返回 []。 改成循环内逐条 try/except 可只丢坏的那一条。
4. 无去重机制
add_facts 不查重，同一事实在多轮研究中被反复抽取会产生近似重复记录， 长期运行会稀释检索多样性。可考虑插入前做向量相似度自查或对 fact_text 做哈希去重。
5. 同步调用限制
query() / add_facts() 是同步阻塞的。 graph.py 部分节点已改为 async def，若 research 节点后续异步化， Milvus 调用需用 to_thread 包裹。
6. research_topic 赋值分散
research_topic 既作为上下文注入提示词，又被写回每条事实作为元数据字段， 但赋值责任分散在 extractor.py 和 research_agent.py 两处，是隐性耦合。
