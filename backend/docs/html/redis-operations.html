一、整体概览

本项目 Redis 主要承担 4 大职责：登录会话 / 任务队列 / 任务事件流 / 搜索结果缓存。 另有 LangGraph 内部的 AsyncRedisSaver 用 Redis 做 checkpoint 状态持久化（间接使用）。

三、auth/session.py — 登录会话

Key：session:{session_id}（Hash）

Hash 字段：

{
    "user_id":     "1",            // str 形式存储
    "username":    "zhangsan",
    "last_active": "2025-...T...",  // ISO8601
}

TTL：86400 秒（24 小时），每次访问自动续期

3.1 创建会话

位置：session.py:35-47 create_session()

Redis 命令作用
HSET key mapping {user_id, username, last_active}写入会话字段
EXPIRE key 86400设置 24h TTL
 
session_id = secrets.token_urlsafe(32)   # 生成 32 字节随机字符串
await r.hset(key, mapping={
    "user_id": str(user_id),
    "username": username,
    "last_active": now,
})
await r.expire(key, SESSION_TTL)          # 24h
return session_id

触发时机：用户 POST /api/login 成功 → routes.py:73

3.2 获取 + 续期

位置：session.py:50-64 get_session()

Redis 命令作用
EXISTS key检查 session 是否存在
HSET key "last_active" now更新最后活跃时间
EXPIRE key 86400续期 24h
HGETALL key读取全部字段
 
exists = await r.exists(key)
if not exists:
    return None
await r.hset(key, "last_active", now)     # 续期
await r.expire(key, SESSION_TTL)
data = await r.hgetall(key)
return data

触发时机：每次 HTTP 请求鉴权（middleware.py:40）

3.3 删除会话

位置：session.py:67-72 delete_session()

Redis 命令作用
DEL key删除会话
 
await r.delete(f"{SESSION_PREFIX}{session_id}")

触发时机：POST /api/logout（routes.py:97-98）

5.2 读取事件（消费者：SSE 端点）

位置：task_queue.py:315-351 read_task_events()

Redis 命令作用

while True:
    result = await r.xread(
        {stream_key: current_id},
        block=5000,
        count=10,
    )
    if result:
        for msg_id, data in messages:
            event_str = data.get("event", "{}")
            current_id = msg_id   # 推进游标
            yield event_str
            # 终止事件检测

                return

六、search_cache.py — 搜索结果缓存

Key：search_cache:{md5(prompt)}（String）

值：搜索结果列表 JSON；TTL：3600 秒（1 小时）

6.1 Key 生成

位置：search_cache.py:36-46, 77-79

def _normalize_query(prompt):
    """去空格/标点/小写"""
    prompt = prompt.strip().lower()
    prompt = re.sub(r'\s+', ' ', prompt)
    prompt = re.sub(r'[，。！？、；：""''「」『』（）()【】\[\]]', '', prompt)
    return prompt.strip()

def _make_key(prompt):
    return f"search_cache:{hashlib.md5(prompt.encode()).hexdigest()}"
设计要点：归一化消除格式噪音（空格、标点、大小写），MD5 保证 key 长度固定。

七、AsyncRedisSaver — LangGraph Checkpoint

LangGraph 内部使用 AsyncRedisSaver 做 state 持久化，由 langgraph.checkpoint.redis.aio 提供。 本项目在 task_queue.py 中初始化一次：

位置：task_queue.py:24, 67-74

from langgraph.checkpoint.redis.aio import AsyncRedisSaver

checkpointer = AsyncRedisSaver(
    REDIS_URL,
    ttl={"default_ttl": 60 * 24 * 7, "refresh_on_read": True},  # 7 天
)
await checkpointer.asetup()  # 自动创建所需 index/key

特性

项值
Key 命名由 LangGraph 内部管理（前缀 langgraph:checkpoint:* 等）
TTL7 天，每次读取自动续期（refresh_on_read=True）
隔离维度LangGraph thread_id（本项目 = task_id）

功能

  • LangGraph 节点执行过程中的 state 自动持久化
  • 支持断点续传：同一 thread_id 重新执行时加载上次 state
  • Human-in-the-Loop（plan 确认等待）依赖此机制 —— awaiting_plan_confirmation 暂停时状态被 checkpoint
间接使用：本项目不直接调用 Redis 命令，所有 LangGraph 内部的 Redis 操作由 AsyncRedisSaver 封装。

十、关键设计要点

10.1 连接管理

模块连接方式特点

10.4 并发与原子性

场景设计
同一 session 多次续期HSET + EXPIRE 都是原子的
Worker 抢占任务Consumer Group 保证消息只被一个 worker 处理（XREADGROUP + XACK）
SSE 多客户端订阅同一 taskRedis Stream 支持多 XREAD 消费者，各自维护 current_id
任务重复提交前端可传同一 task_id，复用 LangGraph checkpoint（断点续传）
MAXLEN 裁剪Redis Stream 的 MAXLEN ~ 近似裁剪（O(1)），精确裁剪用 XTRIM
