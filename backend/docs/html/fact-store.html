七、add_facts 写入（:72-107）

把 facts 转 embedding 后批量插入 Milvus。

核心代码

def add_facts(self, facts: list[dict]) -> int:
    if not facts:
        return 0

    texts = [f["fact"] for f in facts]
    embeddings = self._embed(texts)

    data = []
    now = int(time.time())
    for i, fact in enumerate(facts):
        data.append({
            "vector": embeddings[i],
            "fact_text": fact["fact"],
            "source_url": fact.get("source_url", ""),
            "research_topic": fact.get("research_topic", ""),
            "confidence": float(fact.get("confidence", 1.0)),
            "fact_category": fact.get("fact_category", "strategy"),
            "created_at": now,
        })

    result = self.client.insert(collection_name=self.collection, data=data)
    inserted = result.get("insert_count", len(data))
    logger.info(f"[KB] stored {inserted} facts → Milvus/{self.collection} ...")
    return inserted

阶段 1：决定 Milvus 召回量

if reranker.kb_enabled:
    milvus_limit = max(top_k * 3, 20)    # 多召给 reranker 精排
else:
    milvus_limit = top_k

为什么多召？召回 → reranker 精排 → top_k。Milvus 召回越多，reranker 选择越多，结果越好（但耗时越长）。

阶段 3：Reranker 精排（可选）

if reranker.kb_enabled and len(raw_candidates) > 1:
    fact_texts = [c["entity"].get("fact_text", "") for c in raw_candidates]
    reranked = reranker.rerank(query=topic, documents=fact_texts, top_k=top_k)

    reordered = []
    rerank_scores = {}
    for r in reranked:
        idx = r["index"]
        cand = raw_candidates[idx]
        cand["_orig_idx"] = idx
        reordered.append(cand)
        rerank_scores[idx] = r["score"]

    # 补充未返回的候选
    reranked_indices = {r["index"] for r in reranked}
    for i, cand in enumerate(raw_candidates):
        if i not in reranked_indices:
            cand["_orig_idx"] = i
            reordered.append(cand)

    candidates = reordered
else:
    rerank_scores = {}
    candidates = raw_candidates

关键细节：即使 reranker 启用，仍保留所有候选（包括评分低的），后续由过滤条件进一步筛选。

async def _aembed(self, texts: list[str]) -> list[list[float]]:
    """异步 embedding——用 asyncio.to_thread 包裹同步方法，不阻塞事件循环."""

十一、stats 统计（:257-270）

核心代码

def stats(self) -> dict:
    try:
        stat = self.client.get_collection_stats(self.collection)
        return {"collection": self.collection, "row_count": stat.get("row_count", 0)}
    except ConnectionError as e:
        logger.warning(f"[KB] failed to get collection stats (connection): {e}")
        return {"collection": self.collection, "row_count": "unknown"}
    except Exception as e:
        logger.warning(f"[KB] failed to get collection stats ({type(e).__name__}): {e}")
        return {"collection": self.collection, "row_count": "unknown"}

特点

返回 {"collection": ..., "row_count": N | "unknown"}。连接错误降级为 "unknown"。

14.4 dim 自适应

embedding API 返回的实际维度与 self.embedding_dim 不匹配时，仅警告不抛异常。允许 KB 在 dim 变化时仍能工作。

14.5 潜在改进点

  1. _aembed 未被使用：add_facts 和 query 是同步方法，但内部 HTTP 调用可能阻塞几十毫秒；应改为 async + _aembed
  2. _ensure_collection 在 __init__ 中：如果 Milvus 不可用，构造 FactStore 直接抛 KBConnectionError，无法延迟；考虑改为 lazy 创建
  3. 同步 HTTP 调用：requests.post 是同步阻塞，在异步上下文中需要 aiohttp 或 httpx
  4. 多候选去重逻辑冗余：rerank 后补充未返回的候选可能引入低质量结果
  5. 置信度衰减下限 0.3 是硬编码：可考虑配置化
  6. Milvus 异常分类不细：所有连接异常统一归为 KBConnectionError，缺少超时/资源等子类
