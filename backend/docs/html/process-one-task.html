一、函数概览

_process_one_task(r) 是后台 worker 协程的核心函数 —— 消费一条任务并完整执行。 它由 start_worker()（task_queue.py:116-134）在循环中调用。

位置与签名

# src/agent/task_queue.py:148-308
async def _process_one_task(r: redis.Redis) -> None:
    """消费并执行一个任务."""

核心职责

  1. 从 Redis Stream research:tasks 阻塞消费 1 条任务
  2. 重建 LangChain 消息对象
  3. 定义 emit_token 闭包（用于 LLM 流式输出推送）
  4. 构造 LangGraph 配置（thread_id + _emit_token）
  5. 构造初始 state（支持 plan 确认后的 resume）
  6. 异步执行 LangGraph 多智能体图（Plan → Research → Writer）
  7. 把每个节点事件写入 research:events:{task_id}
  8. 提取最终报告，发射 finalize_answer 或 task_paused
  9. XACK 确认消息 + EXPIRE 设置 24h TTL

输入输出

项说明
输入r：共享的异步 Redis 连接
输出无返回值；副作用全部写入 Redis Stream
调用频率由 start_worker 每 ≤5 秒轮询一次
单次耗时几秒到几分钟（取决于 LangGraph 图执行时间）
并发模型单协程顺序消费；多实例时靠 Consumer Group 抢占

三、阶段 1：消费任务（task_queue.py:148-166）

从 Redis Stream research:tasks 用消费者组抢占一条任务。

核心代码（简化）

result = await r.xreadgroup(
    groupname="research-workers",      # 消费者组
    consumername="worker-1",            # 当前消费者名
    streams={"research:tasks": ">"},   # > = 只读未确认消息
    block=5000,                         # 阻塞 5 秒
    count=1,                            # 每次只取 1 条
)
if not result:
    return                              # 超时，无任务

_, messages = result[0]               # [(msg_id, {field: value})]
msg_id, payload = messages[0]
task = json.loads(payload["task"])
task_id = task["task_id"]

关键设计

机制作用
Consumer Group多 worker 实例时，消息只被一个实例拿到
游标 >只读未确认消息（避免重复消费）
消费者名 worker-1多实例部署时每实例独立名
BLOCK 5000阻塞 5 秒，避免空轮询烧 CPU
COUNT 1每次只取 1 条，单任务粒度
消息状态：XREADGROUP 拿到的消息会进入 PEL（Pending Entries List）， 必须显式 XACK 才能彻底释放 —— 见阶段 10。

五、阶段 3：emit_token 闭包（task_queue.py:178-192）

定义一个异步闭包，用于把 LLM 流式输出的每个 token 实时推送到 Redis 事件流。

核心代码（简化）

async def emit_token(text: str, node: str) -> None:
    """将 LLM token 推送到 Redis 事件流."""
    try:
        event_json = json.dumps(
            {"token": {"text": text, "node": node}},
            ensure_ascii=False,
        )
        await r.xadd(
            f"research:events:{task_id}",
            {"event": event_json},
            maxlen=500,                 # EVENT_STREAM_MAXLEN
        )
    except Exception as exc:
        logger.warning(f"token事件发送失败: {exc}")

闭包捕获的外部变量

变量来源作用
r函数参数Redis 异步连接
task_id解析自 task payload定位事件流 key

写入的事件格式

{
  "token": {
    "text": "你",              // 单个 token（汉字 / 英文单词 / 标点）
    "node": "generate_plan"    // 发起调用的节点名
  }
}
容错设计：try/except 保证单次推送失败不会中断 LLM 流式调用。
上层 astream_step（base_agent.py:256-259）还有第二层 try/except，双重保护。

调用点（项目里只有 2 处）

9.4 提取最终报告

if frontend_event_name == "write" and isinstance(node_output, dict):
    if "messages" in node_output:
        msgs = node_output["messages"]
        ai_msgs = [m for m in msgs if getattr(m, "type", None) == "ai"]

十、阶段 8：任务结束（task_queue.py:274-292）

根据是否有 final_answer_event 判断任务结局。

核心代码（简化）

if final_answer_event:
    # 图正常完成 → 发射 finalize_answer
    await r.xadd(
        f"research:events:{task_id}",
        {"event": json.dumps(final_answer_event, default=str)},
        maxlen=500,
    )
else:
    # 图执行完毕但未生成最终答案 → 在 Plan 确认处暂停
    await r.xadd(
        f"research:events:{task_id}",
        {"event": json.dumps({"task_paused": True})},
        maxlen=500,
    )

两种结局对照

情况触发条件写入事件
正常完成 writer 子图返回（有 final_answer_event） {"finalize_answer": {"messages": [...]}}
暂停等用户 停在 awaiting_plan_confirmation 节点 {"task_paused": true}
判断依据：final_answer_event 仅在 writer 节点返回时被赋值。
如果任务停在 plan 确认（awaiting_plan_confirmation 节点只透传 state），
整个 astream 循环自然结束，final_answer_event 保持 None，走 task_paused 分支。

SSE 端点收到事件后的行为

十一、阶段 9：异常处理（task_queue.py:294-302）

捕获整个 try 块的任何异常，转成 {"error": "..."} 事件推给前端。

except Exception as exc:

十二、阶段 10：清理收尾（task_queue.py:304-308）

finally 块保证消息一定被 ACK、事件流一定被 TTL 清理。

核心代码（简化）

finally:
    # 1. XACK：从 PEL 移除消息，彻底释放
    await r.xack("research:tasks", "research-workers", msg_id)

    # 2. EXPIRE：事件流设 24h TTL，过期自动删除
    await r.expire(f"research:events:{task_id}", 86400)

两件事的作用

操作作用不执行的后果
XACK 从 PEL 移除消息，标识"处理完毕" 消息永远留在 PEL，下次 XREADGROUP 仍会读出（重复消费）
EXPIRE 86400 事件流 24h 后自动删除 Redis 内存无限增长
finally 的关键性：无论成功 / 失败 / 异常，都会执行。
→ 消息最终一定会被 ACK（不会卡在 PEL）
→ 事件流最终一定会被 TTL 清理

容错层级

# 第 1 层：emit_token 内部 try/except
try:
    await r.xadd(...)
except Exception:
    logger.warning(...)               # 单次失败不影响后续

# 第 2 层：astream_step 调用 on_token 时 try/except
try:
    await on_token(token)
except Exception:
    pass                              # 回调失败不能中断流式
双重保护：token 推送失败绝不会中断 LLM 流式输出。

十六、设计要点

16.1 并发与一致性

场景保证机制
多 worker 不重复消费XREADGROUP 消费者组 + > 游标 + XACK
消息不丢失XACK 在 finally，异常也会触发
多 SSE 客户端订阅同一 taskRedis Stream 多消费者语义 + current_id 各自维护
断点续传AsyncRedisSaver 按 thread_id = task_id 持久化 state
Token 流式实时推送emit_token 闭包 → XADD → SSE XREAD 立刻返回

16.2 容错设计

  • XACK 必执行：finally 块兜底
  • EXPIRE 必执行：同上
  • emit_token 容错：双重 try/except
  • LLM 调用容错：3 次重试 + 瞬时/永久错误分类
  • 消息类型过滤：未知类型直接 None 丢弃
  • JSON 序列化兜底：default=str
