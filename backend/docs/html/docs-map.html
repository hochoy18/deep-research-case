1项目概览 Project Overview

Deep Research 是一个基于 LangGraph 的多智能体深度研究后端， 支持人类参与（HITL）的研究计划确认、并行网络搜索、研究反思循环、写作子图辩论评审， 以及基于 Milvus 向量库的跨任务知识库（KB）长期记忆。系统通过 FastAPI + Redis Stream 实现异步任务调度，SSE 推送流式响应。

各层职责

  1. L1 API：HTTP 入口、身份认证、参数解析、任务入队。同步响应 task_id，不等待 LLM。
  2. L2 队列：Redis Stream 任务队列 + 事件流 + Checkpoint 持久化 + 会话存储。支持断点续传。
  3. L3 主图：LangGraph 状态机编排，Plan → HITL 暂停 → Research/Write 路由。
  4. L4 子图：ResearchAgent（搜索循环）和 WriterAgent（写作辩论）两个独立子图，共享 OverallState。
  5. L5 基础类：所有 LLM/MCP/Web 调用的统一入口抽象，含令牌桶速率限制和分类重试。
  6. L6 KB：长期记忆层，从搜索摘要抽取原子事实，存 Milvus 向量库，下次检索复用。

def _route_after_critic(state, config) -> str:
    """四重退出保险：防御 Critic 自评偏差"""
    revision = state.get("revision_count", 0)
    if state.get("ready_for_polish"):  return _CITE_AND_POLISH  # ① LLM 自评
    if state.get("critic_score", 0) >= 8.0:  return _CITE_AND_POLISH  # ② 硬阈值
    if state.get("critic_score", 0) >= 6.0 and revision >= 1:  return _CITE_AND_POLISH  # ③ 软阈值
    if revision >= state.get("max_revisions", 3):  return _CITE_AND_POLISH  # ④ 强制上限
    return _DRAFT

HITL 设计核心要点

  • 暂停三要素：透传节点 lambda state, config: state + 无出边 + AsyncRedisSaver
  • 图自然结束而非后台挂起：等待时间无限，零后端线程/LLM 资源
  • 二次 invoke 幂等：generate_plan 看到 plan_status=confirmed 返回 {}
  • evaluate_plan 三路路由：unconfirmed→等待 / plan 空→replan / 否则→confirm_plan
  • confirm_plan 三种确认路径：关键词短路 / LLM 兜底 / LLM 隐式确认（乐观偏向）
  • plan_messages 隔离：独立累计避免 replan 污染主 messages
  • 前端契约：必须 append HumanMessage + 改 plan_status="confirmed"
改进方向：采用显式 interrupt_before + checkpointer + Command(resume=...) 模式，将恢复交给 LangGraph runtime 而非前端拼隐式 state。

📄 subagent_researcher/generate-queries.html + _generate_queries_explain.html — _generate_queries

ResearchAgent 子图入口：把研究主题拆解为 N 条独立、可并行、已被 KB 去重的搜索查询。两份文档互补。

  • 6 步流程：配置初始化 → KB 检索 → 拼装 known_facts_text → LLM 生成 → 失败降级 → 返回状态
  • 4 种 KB 模式：off / inform / freshness / lifecycle，由环境变量切换
  • Pydantic 强约束：SearchQueryList TypedDict（query + rationale）
  • 失败兜底：LLM 全部失败 → 降级为 1 条原始主题，保证 fan-out 不空指针

async def _generate_queries(state, config):
    store = _get_kb_store()
    if store:
        hits = store.query(topic, top_k=20, min_confidence=0.6,
                           max_age_days=max_age, decay=decay,
                           lifecycle_mode=use_lifecycle)
        known_facts_text = format_kb_hits(hits)
    agent = JsonAgent(model_id=..., keys=SearchQueryList)
    agent.set_step_prompt(query_writer_instructions)
    result = agent.step(research_topic=topic, known_facts=known_facts_text, ...)
    if not isinstance(result, SearchQueryList):
        return {"search_query": [get_research_topic(state["messages"])]}  # 兜底
    return {"search_query": result.query}

📄 main_graph/confirm_plan.html — confirm_plan 节点

11项目亮点 Project Highlights

🏗️ HITL 断点续传

透传 lambda + 无出边 + AsyncRedisSaver 三要素实现暂停；图自然结束，零线程/LLM 资源占用。

📚 KB 闭环（读旧写新）

查询前 Milvus 检索已有 facts → LLM prompt 增强避免重复；搜索后 FactExtractor 抽 facts → 写新 facts 复用知识。

🛡️ 优雅降级

"失败即降级、不污染主流程"工程哲学：KB 异常被 logger.warning 吞掉返回空列表，KB 挂掉主图仍能正常生成报告。

🚀 并行扇出

LangGraph Send API + operator.add reducer 把 N 个并行副本的输出自动累积，研究时间从 O(Nt) 降到 O(t)。

📡 流式输出 6 层链路

LLM → astream_step → on_token → emit_token → Redis XADD → SSE → 浏览器，实时推送 token。

🔄 四重退出保险（WriterAgent）

ready_for_polish / score≥8.0 / score≥6.0+revision≥1 / revision≥max_revisions，多层防御 Critic 自评偏差。

🎯 双重退出保险（ResearchAgent）

is_sufficient OR loop≥max_loops，防止研究循环死循环 + LLM 自评失误。

🔍 旁路评估框架

eval 子系统不修改主链路任何文件，只 import 并调用，LLM-as-Judge 端到端 5 维 + 组件级 7 维。

⏱️ 异步任务调度

Redis Stream 任务队列 + Consumer Group + Worker XREADGROUP，支持多 worker 抢占、断点续传、24h 自动清理。
