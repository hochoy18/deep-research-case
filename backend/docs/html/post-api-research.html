一、整体概览

POST /api/research 是 Deep Research 多智能体研究链路的起点。 接口本身只做三件事：解析 body入队 Redis Stream写用户关联，然后立即返回 task_id。

真正的 AI 重活（LLM 调用、搜索循环、报告写作）由后台 worker 协程异步完成 —— 本接口范围内不展开。

一句话总结

同步入口 + 异步执行：POST 写入 Redis Stream 后立即返回，不等 LLM、不阻塞用户。

接口元信息

项值
方法 / 路径POST /api/research
鉴权Cookie session_id（AuthMiddleware 白名单外必填）
请求体JSON：messages / initial_search_query_count / max_research_loops / reasoning_model / plan_status / plan / task_id
成功响应200 {"task_id": "...", "stream_url": "/api/research/{id}/stream"}
主要存储Redis Stream research:tasks + DB Table user_threads
同步耗时典型 < 100ms（鉴权 + 解析 + XADD + 一次 SQL）

十二、补充说明

为什么 POST 这么快？

  • 鉴权：只查一次 Redis Hash（HGETALL，单 round-trip）
  • 入队：Redis XADD 是 O(1) 操作
  • 写关联：单条 SELECT + INSERT，无复杂查询
  • 零 LLM 调用：所有 AI 工作都在 worker 协程里异步执行

task_id 复用场景

前端可以在第二次提交时回传同一个 task_id，典型场景：

  • 用户刷新页面后想继续任务
  • 同一任务的 plan 确认后再次提交（plan_status="confirmed"）

后端在 task_queue.py:96-97 检测：

if not task_id:
    task_id = str(uuid.uuid4())
# 否则复用前端传入的 task_id

复用同一 task_id 后，LangGraph 的 AsyncRedisSaver 会加载之前的 checkpoint 状态，实现断点续传。
