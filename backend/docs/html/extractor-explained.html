一、模块定位

FactExtractor 是 Deep Research 知识库（KB）子系统的写入端： 把 Web 搜索得到的摘要文本（非结构化）转成可被向量检索的结构化 fact 对象， 再交给 FactStore（Milvus）落库。

1.2 核心职责

  • 接收上游 _web_search 节点产出的摘要文本（已包含 URL 引用）
  • 构造带 EXTRACTION_INSTRUCTIONS 的 LLM prompt，调用 Agent.step()
  • 从 LLM 输出中鲁棒地抽取 JSON（Post.extract_pattern）
  • 用 _validate 过滤/规整事实：截断 confidence、默认 category、限长 10 条
  • 返回 list[dict] 给调用方；任何异常都降级为空列表

1.3 输入输出

项说明
输入summary: str（必填，≥50 字符） + research_topic: str（可选上下文）
输出list[dict]，每个 dict 形如 {fact, source_url, confidence, fact_category}
异常行为任何错误都返回 []，绝不抛出（保证 KB 写入失败不影响主流程）
LLM 模型默认 deepseek-v4-pro，构造时可覆盖

        self.model_id = model_id

    def extract(self, summary: str, research_topic: str = "") -> list[dict]: ...
    @staticmethod
    def _validate(facts: list) -> list[dict]: ...

3.2 成员清单

成员类型说明
model_id 实例属性 (str) LLM 模型标识，__init__ 时传入，默认 deepseek-v4-pro
extract(summary, topic) 实例方法 主入口：摘要 → facts 列表
_validate(facts) 静态方法 规整：过滤非 dict、过滤空 fact、裁剪 confidence、默认 category

模块级 prompt 字符串，模板里有 2 个 {key} 占位符，由 Agent.step() 通过 prompt_format() 替换为真实值。

4.2 步骤分解

  • 前置检查：summary 为空或 len < 50 直接返回 []，跳过 LLM 调用
  • 构造 Agent：Agent(model_id=self.model_id)，每次调用都新建（轻量）
  • 注入 Prompt：set_step_prompt(EXTRACTION_INSTRUCTIONS)
  • 截断 summary：summary[:8000]，防止超长 prompt 触发 token 上限
  • 调用 LLM：agent.step(research_topic=..., summary=...)，内部有 3 次重试
  • 抽 JSON：Post.extract_pattern(raw, "json") 处理 LLM 输出的各种格式
  • 解析：json.loads()，捕获 JSONDecodeError
  • 类型校验：必须是 list，否则降级
  • 规整：_validate(facts)
  • 返回：list[dict]

6.2 _clean_json 修复常见 LLM 错误

def _clean_json(text: str) -> str:
    """Fix common LLM JSON formatting errors (trailing commas, etc.)."""
    # Remove trailing commas before } or ]
    text = re.sub(r",\s*([}\]])", r"\1", text)
    return text

只修复尾随逗号这一类最常见的 LLM JSON 错误。其他错误（如缺引号、嵌套错误）由 json.loads 自然抛 JSONDecodeError。

6.3 三种典型 LLM 输出形态

形态示例抽取路径
① 完美 
```json

  {"fact": "...", ...}
]
```
 代码块正则一次匹配
② 嵌入文本 
以下是事实列表：

请基于以上...
 代码块失败 → fallback 扫描所有 {} → 找最长合法 JSON
③ 彻底坏掉

 所有 fallback 都失败 → 返回原 text → json.loads 抛异常 → 降级 []

7.2 字段规整规则

valid.append({
    "fact":          fact_text.strip(),                    # strip 首尾空白
    "source_url":    f.get("source_url", ""),              # 默认空串
    "confidence":    min(1.0, max(0.0, float(f.get("confidence", 0.7)))),  # clamp
    "fact_category": f.get("fact_category", "strategy"),   # 默认 strategy
})
字段处理默认值
factstrip()，丢弃 <10 字符的无（必填）
source_url原样保留""
confidenceclamp(0.0, 1.0)0.7
fact_category原样保留"strategy"
总数上限最多 10 条，超出截断
坑点：float(f.get("confidence", 0.7)) 没有 try/except —— 如果 LLM 返回 "confidence": "high" 这种非数字，会抛 ValueError，被外层 except (ValueError, TypeError) 捕获，降级为 []。整批丢掉而不是丢掉这一条。

8.2 异常捕获矩阵

异常类型触发场景处理
JSONDecodeErrorLLM 输出无法解析为 JSONwarning + []
ValueErrorfloat() 失败（confidence 非数字）warning + []
TypeErrorf.get() 失败warning + []
Exception（兜底）任何未预期错误warning + []
PermanentError（Agent 抛）LLM 调用永久错误（如鉴权失败）Agent 内层处理，extract() 不会看到
设计哲学：KB 是可选增强，不能因为抽取失败就让整次研究崩溃。所以 extract() 的契约是 "要么返回 list，要么返回 []，永远不抛"。

十一、设计要点

11.1 容错优先

  • 任何环节失败都返回 []，不抛出
  • JSON 抽取有多层 fallback
  • LLM 调用有重试 + 退避

11.2 可观测性

  • logger.info：成功时记录提取数量
  • logger.debug：摘要过短跳过（避免 INFO 噪音）
  • logger.warning：JSON/校验失败

11.3 资源控制

  • summary[:8000] 截断：防止超长 prompt 撑爆 token
  • max 10 facts：限制输出体积 + 控制 KB 写入压力
  • summary < 50 跳过：避免无意义 LLM 调用

11.4 数据规整

  • confidence 强制 clamp 到 [0, 1]
  • fact_category 缺省给 strategy（覆盖面最广）
  • source_url 缺省给空串（不抛 KeyError）

11.5 单例与轻量

  • FactExtractor 自身不持有 LLM 连接（懒加载），所以单例安全
  • 每次 extract() 内部新建 Agent，LLM 连接由 OpenAICompatibleLLM 内部管理

11.6 潜在改进点

  • per-fact 容错：现在一条 confidence 非数字会让整批 []，可以改为跳过该条继续处理
  • trace_id：抽取阶段记录 trace_id，方便后续和 KB 中的 facts 关联调试
  • 批量抽取：当同一研究有多条 query 时，可以合并多篇 summary 一次提取，省 LLM token
  • async 版本：extract() 是同步的（用 Agent.step），可以加 aextract() 避免阻塞主流程
