一、模块定位与职责

extractor.py（143 行）定义了 FactExtractor 类，唯一职责： 把 _web_search 产出的非结构化搜索摘要，通过 LLM 抽取为 0~N 条 结构化事实字典，供 FactStore.add_facts 写入 Milvus。

3 件事

职责实现
摘要长度保护len(summary) < 50 早返回 []，节省 LLM 调用
LLM 结构化抽取Agent + EXTRACTION_INSTRUCTIONS 提示词约束输出为 JSON 数组
规整与限流_validate() 过滤、confidence 钳位、限 ≤ 10 条
核心约束：任何路径失败都返回 list（可能为空）， 绝不抛异常。这是为了保证 KB 写链路失败不会阻塞 ResearchAgent 主流程。

六、_validate() 校验规则

_validate 是 静态方法，对 LLM 返回的 facts 列表做 4 道规整。

@staticmethod
def _validate(facts: list) -> list[dict]:
    valid = []
    for f in facts:
        if not isinstance(f, dict):
            continue
        fact_text = f.get("fact", "").strip()
        if not fact_text or len(fact_text) < 10:
            continue
        valid.append({
            "fact":          fact_text,
            "source_url":    f.get("source_url", ""),
            "confidence":    min(1.0, max(0.0, float(f.get("confidence", 0.7)))),
            "fact_category": f.get("fact_category", "strategy"),
        })
        if len(valid) >= 10:
            break
    return valid

4 条规整规则

规则行为防御什么
isinstance(f, dict) 非 dict 直接丢弃 列表里混进非字典元素
len(fact_text) < 10 太短的 fact 丢弃 LLM 偶尔返回空字符串
confidence 钳位 min(1.0, max(0.0, x)) LLM 输出越界值（>1.0 或 <0.0）
截断到 ≤ 10 条 len(valid) >= 10 → break 防 LLM 输出 N+ 条

默认值兜底

字段默认值
source_url""
confidence0.7（中等）
fact_category"strategy"

3 个 catch 块

try:
    json_str = Post.extract_pattern(raw, pattern="json")
    facts = json.loads(json_str)
    if isinstance(facts, list):
        facts = self._validate(facts)
        logger.info(f"... extracted {len(facts)} facts ...")
        return facts
except json.JSONDecodeError as exc:
    logger.warning(f"JSON parse failed — LLM returned malformed JSON: {exc}")
except (ValueError, TypeError) as exc:
    logger.warning(f"data validation failed ({type(exc).__name__}): {exc}")
except Exception as exc:
    logger.warning(f"failed to parse facts ({type(exc).__name__}): {exc}")

return []   # 任何失败路径
为什么"失败不抛异常"
  • _web_search 是 ResearchAgent 子图的关键节点
  • KB 写失败不应该让整个研究流程挂掉
  • 返回 [] 让 FactStore.add_facts 拿到空列表，跳过 Milvus 写入
  • 日志保留了完整的失败原因供运维排查

十一、关键设计要点

设计点含义
用 Agent 而非 JsonAgent 故意不用 Pydantic schema 强约束，让 LLM 有自然语言灵活性；用 Post.extract_pattern 后置兜底
[:8000] 硬截断 防御单条 summary 过长触发 LLM token 上限
早返回 < 50 字符 节省 LLM 成本 + 避免低质抽取
_validate 钳位 confidence 防御 LLM 输出越界值（>1.0 或 <0.0）
统一 try/except → return [] KB 写失败绝不阻塞 ResearchAgent 主流程
默认 fact_category="strategy" LLM 漏标时的安全 fallback
最多 10 条（双层防护） prompt 提示 + 代码 break，双重约束
单例 _kb_extractor 进程共享一个 LLM 客户端（见 research_agent.py:78-82）
research_topic 兜底字符串 "(extracting facts)" 防止 prompt 渲染失败
为什么不用 JsonAgent(keys=FactList)？

提示词里 fact_category 是枚举字符串，LLM 输出偶尔会有拼写错误（如 "Market-Data"）， Pydantic 强校验会导致整个抽取失败 → 返回 []。当前实现更宽松：忽略拼写错误， 走默认值 "strategy"。

十二、潜在改进点

#问题改进方向
1 不用 Pydantic schema 强约束 改用 JsonAgent(keys=FactList) 更稳健，可省掉 json.loads 异常分支
2 Agent(self.model_id) if self.model_id else Agent() 死代码 简化为 Agent(self.model_id)
3 8KB 硬截断无 marker 建议按段落或句子边界截，避免切碎关键事实
4 category 默认 "strategy" 不一定合适 应根据上下文语义推断（如含"市场"→ market_data）
5 10 条限制"先到先得" 未按 confidence 排序，可能丢掉高分事实 → 建议 sorted(facts, key=lambda x: -x["confidence"])
6 KB 抽 facts 是同步阻塞 LLM 调用 多个 web_search 并行时会触发多个 LLM 请求，可能限流

十三、一句话总结

FactExtractor.extract() = LLM 结构化抽取 + JSON 后置解析 + 校验规整 + 失败兜底 return []

它把一段非结构化搜索摘要，转化为 0~10 条带 confidence + source_url + fact_category 的事实字典， 由 FactStore.add_facts 写入 Milvus；任何路径失败都返回 []， 绝不阻塞 KB 写链路。
