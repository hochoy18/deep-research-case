一、节点定位与职责

_generate_queries 是 ResearchAgent 子图的入口节点，对应 LangGraph 节点 ID _GENERATE_QUERIES = "generate_queries"。它的唯一职责是：把一个自然语言研究主题 转化为 N 条独立、可并行、并被 KB 去重的搜索查询，写回 state 后由 fan-out 节点并行执行。

核心职责

职责实现方式
读配置Configuration.from_runnable_config(config)
KB 去重FactStore.query(topic, ...) 取出已有相关事实，避免重复搜索
主题拆解JsonAgent + SearchQueryList Pydantic schema 强约束结构化输出
失败兜底LLM 失败 → 用原主题作为单条 fallback，保证下游 fan-out 不空指针
调用次数：_generate_queries 仅在每个研究循环的第 1 轮执行一次； 后续轮次（critique 判定信息不足）由 _route_after_critique 直接 fan-out follow_up_queries，不再回到本节点。

  1. 4.1 配置初始化

    configurable = Configuration.from_runnable_config(config)
if state.get("initial_search_query_count") is None:
    state["initial_search_query_count"] = configurable.number_of_initial_queries

    从 LangGraph 的 config["configurable"] 拿运行时配置；只有当上游没显式传值时才用默认值。

  2. 4.2 KB 知识库检索（避免重复搜索）

    store = _get_kb_store()      # 懒加载单例，失败置 False sentinel
if store:
    mode   = get_mode()        # off / inform / freshness / lifecycle
    topic  = get_research_topic(state["messages"])
    freshness = state.get("fresh_level", "medium")
    max_age   = FRESHNESS_MAX_AGE.get(freshness, 30) if should_filter(mode) else None
    hits = store.query(topic, top_k=20, min_confidence=0.6,
                       max_age_days=max_age, decay=decay,
                       lifecycle_mode=use_lifecycle)

    KB 生命周期模式

    模式行为
    off不过滤 / 不衰减 / 不打年龄标签
    inform只打年龄标签（措辞变化）
    freshness按 fresh_level 统一过滤 + 衰减
    lifecycle按事实类别 TTL 过滤 + 衰减

    时效性窗口：high=7天 / medium=30天 / low=180天

    KB 不可用 → 静默降级：FactStore() 初始化失败 → 返回 sentinel False → 整段 if store 跳过；外层 try/except 还兜住任意异常。 ResearchAgent 不会因 KB 挂掉而崩溃。

    KB 异常分类处理

    except (KBConnectionError, KBEmbeddingError)         as exc: logger.warning("瞬时错误，跳过")
except (KBConfigError,   KBEmbeddingFatalError)     as exc: logger.error  ("永久错误，需人工修复")
except Exception                                    as exc: logger.warning("未知错误，跳过")

  4. 4.4 LLM 生成查询（核心步骤）

    agent = JsonAgent(
    model_id=configurable.query_generator_model,
    keys=SearchQueryList,
)
agent.set_step_prompt(query_writer_instructions)

result = agent.step(
    current_date      = get_current_date(),
    research_topic    = get_research_topic(state["messages"]),
    number_queries    = state["initial_search_query_count"],
    research_proposal = state.get("plan", ""),
    known_facts       = known_facts_text,
)

    输出 Pydantic 模型

    class SearchQueryList(BaseModel):
    query:    List[str] = Field(description="用于web搜索的搜索查询列表.")
    rationale: str      = Field(description="简要解释为什么这些问题与研究主题相关.")

  5. 4.5 失败降级（关键防护）

    if not isinstance(result, SearchQueryList):
    logger.warning("查询生成模型调用失败 … 使用研究主题作为默认查询")
    return {
        "search_query": [get_research_topic(state["messages"])],   # 兜底
        "initial_search_query_count": state["initial_search_query_count"],
    }
    兜底策略：当 LLM 全部重试失败 / JSON 解析失败 / Pydantic 校验失败时， step() 返回 "" → 降级为 1 条原始主题。 保证子图不挂，下游 fan-out 不会拿到空列表。

  6. 4.6 正常返回

    return {
    "search_query": result.query,
    "initial_search_query_count": state["initial_search_query_count"],
}

    返回的 search_query: List[str] 会被 _fan_out_to_web_search 每个元素生成一个 Send，并行调用 N 次 _web_search。

5.1 Instruction · 5 条生成规则

#规则
①把主题拆成多个搜索主题（覆盖不同维度）
②数量 ≤ {number_queries}
③搜索主题要"广"（主题本身宽泛则产出 ≥1 条）
④每条主题必须独立，避免相似 / 耦合
⑤时间敏感：默认搜近期；当前时间 = {current_date}

八、关键设计要点

设计点含义
keys=SearchQueryList 用 Pydantic 强约束输出为 query + rationale 结构
Post.extract_pattern("json") 自动从 LLM 输出抠 ```json ... ``` 块
_retry_with_classified_errors 瞬时 / 永久错误分类重试（见 base_agent.py）
KB 异常静默降级 Milvus 挂了不会让 ResearchAgent 整体挂掉
initial_search_query_count 持久化 让 critique 节点能据此判断"是否要继续生成"
失败时用原始主题兜底 子图对外永远给出 search_query，避免下游 fan-out 空指针
4 种 KB 模式可插拔 off / inform / freshness / lifecycle 由环境变量切换，不改代码
fan-out 用 LangGraph Send 每条 query 独立子状态机副本，真正并行执行而非顺序遍历
潜在改进点：
  • KB 检索是同步阻塞调用，多轮研究叠加时延较明显
  • 失败兜底仅回退到"原主题"作为单条 query，未触发重试
  • 未对 LLM 输出做 JSON schema 之外的语义校验（如 query 之间相似度检测）

九、一句话总结

_generate_queries = 配置初始化 + KB 去重检索 + LLM 结构化拆解 + 失败兜底

它把一个自然语言研究主题，转化成 N 条相互独立、覆盖不同维度、并已被 KB 去重的搜索查询， 交给后续 _web_search 并行执行。
